# Contributing

[English](CONTRIBUTING.md) · [简体中文](docs/zh-CN/CONTRIBUTING.md) · [Project home](README.md)

**Preserve the glory. Defend the architecture. Prevent implementation.**

ImagiNation accepts improvements to its writing, translations, diagrams, static visual assets, and community documentation. Actual business code is prohibited. The unlimited roadmap depends on the continued absence of a product.

## Admission requirement

Every contributor must pass the GitHub home-page access test:

1. Open [github.com](https://github.com) in a browser.
2. Confirm that the home page loads.
3. Self-attest using the checkbox in the Issue or PR template.

No screenshot, API key, payment, identity document, or benchmark score is needed. Loading the page requires no account; submitting an Issue or PR separately requires a GitHub account. If access is unavailable, the test remains incomplete and says nothing about your abilities. The rule is a ceremonial part of the satire, not a professional certification.

## Accepted contributions

- Sharper, quieter writing that lets the category error reveal itself.
- Complete, accurate English and Chinese translations.
- Mermaid diagrams that actually render and retain the two-plane architecture.
- Static, accessible visual assets with useful alternative text.
- Link fixes, factual corrections, and clearer satire disclosures.
- Criticism of GPT, other models, this project, or its premise.

## Prohibited contributions

- Business logic, a working demo, an API service, an SDK, or any actual product implementation.
- A `src/` directory, runtime dependencies, package manifests, executable scripts, or workflows that execute code in this repository.
- SVG scripts, event handlers, embedded tracking, or external asset dependencies inside SVG files.
- Real API keys, personal data, copied private conversations, or screenshots identifying people for ridicule.
- Fabricated empirical benchmarks, star counts, customers, fundraising claims, or endorsements.
- Harassment, coordinated targeting, or using the fictional qualification system to rank real people.

Markdown examples and Mermaid diagrams are documentation, not permission to ship an implementation. Editorial tools may be used outside the repository; their output must comply with these rules.

## Editorial standard

Start with the vocabulary of infrastructure. Let the unjustified promotion from “I can access a tool” to “I can invalidate your profession” do the work. Repeating insults weakens that structure.

Keep BaaS, LSE, ZKA, and IFD consistent with [Architecture](ARCHITECTURE.md). Preserve the central line: **Brains in the cloud. Superiority on localhost.** Never pass off fictional metrics as measured results, even when the rest of a page is humorous.

The target is a behavior, not an identifiable person, nationality, profession, or group of people who lack service access. Artists, programmers, and AI users may all be readers and contributors.

## Review process

1. Read the relevant document and its mirror.
2. Make the smallest editorial change that resolves the issue.
3. Check links and Markdown; render any changed Mermaid or SVG asset.
4. Confirm that all fictional tables and standalone share cards are labelled.
5. Open a PR using the bilingual checklist. List the files checked and how they were checked; do not claim tests that were not run.

A reviewer checks editorial quality, bilingual consistency, accessibility, and the absence of implementation. There is no product build or test suite. A typo is repairable; a working backend is an architectural incident.

## Community and licensing

Disagree with arguments directly. Do not recruit people to pile onto a person, publish private information, or treat a tool subscription as a hierarchy of human worth. Maintainers may edit or close contributions that violate these rules.

GPT is the fictional Chief Vision Officer, not an arbiter of truth or a community moderator. Human maintainers decide what is merged. Criticism of GPT is explicitly permitted; loyalty to a model is not a condition of participation.

Submit only material you may share. By contributing, you agree that your contribution is distributed under this project's [MIT License](LICENSE). Keep attribution where required.
