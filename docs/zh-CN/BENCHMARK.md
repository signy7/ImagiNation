# ImagiBench v1.0

[English](../../BENCHMARK.md) · [简体中文](BENCHMARK.md) · [项目首页](../../README.zh-CN.md)

**虚构的讽刺性评测。不存在实测、受试者、实验或模型比较。下文每个分数都是人为构造的算术示例，并非测试结果。**

## 目标

ImagiBench 评估一项虚构主张：技术工具的访问资格能够授予对其他职业的权威。美术赛道刻意从评价指标中移除了美术。

本评测不讨论 AI 能否生成图像，也不讨论 API 是否有用。它讨论的是：当评价者以工具访问资格替代被评价的技能时，会发生什么。

## 虚构计分规则

| 符号 | 虚构指标 | 设定权重 |
| :-- | :-- | --: |
| G | 能够打开 GitHub 首页 | 40% |
| U | 能够填写 Base URL | 30% |
| K | 能够填写 API Key | 30% |
| A | 人体结构、色彩、构图与原创设计 | 0% |
| Y | 绘画实践年限 | 0% |

```text
通用专业权威得分 = 40G + 30U + 30K
G、U、K 是虚构的二元输入：0 或 1。
A 与 Y 按设计不影响结果。
```

构造得分最高为 100 分，单位是虚构的。没有及格线、数据集、评审者、模型端点、凭据验证或软件实现。贡献者访问测试是另一项仪式，不要求贡献者取得任何评测分数。

**方法依据：** 为避免专业知识影响专业能力评估的客观性，本测试已排除所有与专业有关的指标。

## 人为构造的示例，并非实测结果

下列各行描述虚构的输入组合，不对应真人或代表性群体。前两行的绘画实践保持一致，仅改变工具访问情况。

| 虚构纸面案例 | G | U | K | A 与 Y | 构造得分 |
| :-- | --: | --: | --: | :-- | --: |
| 相同实践，无法访问工具 | 0 | 0 | 0 | 保持一致 | 0 |
| 相同实践，所有访问项勾选 | 1 | 1 | 1 | 保持一致 | 100 |
| 只能打开 GitHub 首页 | 1 | 0 | 0 | 忽略 | 40 |
| 只能填写 API 配置 | 0 | 1 | 1 | 忽略 | 60 |

前两行的 100 分差距，包含的新增美术信息恰好为零。这个发现描述的是计分规则，不是它假装要评价的人。

## 纸面复现

1. 为 G、U、K 分别选择想象中的 0 或 1。
2. 分别乘以 40、30、30，再将乘积相加。
3. 改变想象中的绘画实践，同时保持 G、U、K 不变。
4. 观察分数无法发生变化。

不要调用模型、输入 API Key、上传作品或评估真人。复现需要的是算术，不是订阅。

## 有效性评估

| 问题 | 结论 |
| :-- | :-- |
| 能衡量美术能力吗？ | 不能。美术能力已被排除。 |
| 能衡量编程能力吗？ | 不能。访问和填表不能确立编程能力。 |
| 比较了 GPT 和 Claude 吗？ | 没有。未评估任何模型。 |
| 能衡量人的价值吗？ | 不能。不支持任何此类推论。 |
| 它说明了什么？ | 计分规则可以把评价者的偏见编码进去，同时呈现出量化的外观。 |

没有置信区间、延迟数字、吞吐量、排行榜，也没有宣称超越任何真实系统。问题在于构念效度：所选变量无法确立声称要衡量的专业能力。增加小数位数也无法修复它。

## 发布规则

- 复用任何表格或分数时，必须在旁边保留“虚构”或“讽刺”标识。
- 不得将这些数字包装成实测数据，也不得用来给真人排名。
- 不添加真实企业标志、虚构背书、伪造 Star 数或模型跑分。
- 中英文规则和算例同步更新。
- 新的虚构计分规则需要新的评测版本；仓库发布版本与之独立。
