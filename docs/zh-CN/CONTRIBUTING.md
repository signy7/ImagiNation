# 贡献指南

[English](../../CONTRIBUTING.md) · [简体中文](CONTRIBUTING.md) · [项目首页](../../README.zh-CN.md)

**维护荣光，捍卫架构，杜绝实现。**

ImagiNation 接受对文字、翻译、图表、静态视觉素材与社区文档的改进。严禁实际业务代码。无限的路线图依赖于产品持续缺席。

## 准入要求

每位贡献者必须通过 GitHub 首页访问测试：

1. 用浏览器打开 [github.com](https://github.com)。
2. 确认首页加载成功。
3. 在 Issue 或 PR 模板的复选框中自行确认。

不需要截图、API Key、付款、身份证明或评测分数。加载页面不需要账号；另行提交 Issue 或 PR 需要 GitHub 账号。如果无法访问，测试尚未完成，这与你的能力无关。该规则是讽刺设定中的仪式，不是专业认证。

## 接受的贡献

- 更准确、更克制的文字，让类别错置自行显露。
- 完整、准确的英文与中文翻译。
- 真正能够渲染且保留双平面架构的 Mermaid 图。
- 具备实用替代文本的、易于阅读的静态视觉素材。
- 链接修复、事实纠错和更清晰的讽刺标识。
- 对 GPT、其他模型、本项目或其前提的批评。

## 禁止的贡献

- 业务逻辑、可工作的演示、API 服务、SDK 或任何实际产品实现。
- `src/` 目录、运行依赖、包清单、可执行脚本或在本仓库执行代码的工作流。
- SVG 脚本、事件处理器、嵌入式追踪，或 SVG 文件内的外部素材依赖。
- 真实 API Key、个人数据、转载的私密对话，或用于点名嘲讽的可识别个人截图。
- 伪造的实测跑分、Star 数、客户、融资声明或背书。
- 骚扰、组织围攻，或利用虚构资格体系给真人排名。

Markdown 示例和 Mermaid 图是文档，不是交付实现的许可。可以在仓库外使用编辑工具，其输出必须遵守上述规则。

## 编辑标准

从基础设施的语言开始，让“我能访问工具”被无端升级为“我能否定你的职业资格”的过程自行发挥作用。反复辱骂会削弱这种结构。

BaaS、LSE、ZKA、IFD 的含义应与[架构文档](ARCHITECTURE.md)一致。保留核心句：**大脑部署在云端，优越感部署在本地。** 即使整页带有幽默色彩，也不得将虚构指标包装为实测结果。

批评对象是一种行为，不是某个可识别个人、国籍、职业，或无法访问服务的人群。画师、程序员和 AI 使用者都可以是读者与贡献者。

在同一个 PR 中更新两种语言。保持章节、主张、限制、虚构权重和算例一致，可以使用各自自然的表达。英文 MIT 许可证是授权文本，中文译文仅供阅读参考。Issue 与 PR 模板在同一文件中提供两种语言。首屏和传播卡片也有对应的语言版本。

## 审核流程

1. 阅读相关文档及其镜像。
2. 做出足以解决问题的最小文字修改。
3. 检查链接和 Markdown；渲染修改过的 Mermaid 或 SVG 素材。
4. 确认所有虚构表格与独立传播卡片均有标识。
5. 使用双语清单提交 PR，写明检查了哪些文件、如何检查；不要声称运行过未运行的测试。

审核者检查编辑质量、双语一致性、可读性以及是否混入实现。本项目没有产品构建流程或测试套件。错别字可以修复，可工作的后端属于架构事故。

## 社区与许可

直接反驳论证。不要招募他人围攻个人、发布私密信息，或把工具订阅视作人的价值等级。维护者可以编辑或关闭违反规则的贡献。

GPT 是虚构的首席愿景官，不是真理裁判或社区管理员。人类维护者决定合并内容。明确允许批评 GPT；忠于某个模型不是参与条件。

只提交你有权分享的内容。参与贡献即表示同意按本项目的 [MIT 许可证](../../LICENSE)分发你的贡献。按要求保留署名。
